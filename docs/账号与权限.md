# 账号与数据权限说明

设置 → **账号与权限**，给账号选一个「职位」即可，不需要理解技术术语。

## 一、四档职位与可见范围

| 职位 | 可见范围 | 说明 |
| --- | --- | --- |
| 总经理 | **全部数据：所有组 / 所有人** | 询价、订单、跟进、分析全部可见 |
| 副总经理 | **全部数据：所有组 / 所有人** | 同上 |
| 部门主管 | **本部门全部数据**（该部门下所有小组） | 需选择部门；不选小组＝整个部门 |
| 组长 | **本组全部数据**（所选小组的全体成员） | 需选择部门 + 小组 |
| 普通成员 | **只看自己**录入 / 参与的数据 | 录询价时销售自动锁定为本人 |

**写入规则**：只有「全部数据」权限可以改别人的记录；主管/组长能**看**全组，但**只能改自己名下**的记录（含自己作为采购人员参与的单）。这是按你之前的要求「组长只看不改别人的」实现的。

## 二、销售侧 vs 采购侧

数据范围按账号所属部门自动区分：

- **销售部（及其它非采购部门）**：按询价的「**销售人员**」字段判定 —— 组长看到本组每位销售的询价。
- **采购部 / 销售支持组**：按询价的「**采购人员**」字段判定 —— 采购组长看到本组采购人员参与的全部询价；采购部主管选「部门主管 + 采购部」时，看整个采购部（质量组 / 采购一组 / 采购二组）。

## 三、账号的显示名很重要

数据范围里的「自己」是按**显示名**和询价里的销售人名匹配的（不区分大小写）。
所以：销售人员的账号显示名要写成询价里用的名字（如 `Vera`），否则会出现「能看全组、却改不了自己的单」。

## 四、建号规则：账号必须来自组织架构

在「账号与权限」里新增账号时，**不能手输账号名**，必须按组织架构选人：

**部门 → 小组 → 人员 → 职位 → 初始密码**

- 登录名 = 组织架构里姓名的**小写**（如 `Echo` → `echo`），显示名 = 组织架构里的姓名 —— 保证和询价里的销售人名始终一致；
- 部门/小组/职位会按所选人员的组织角色**自动预填**（销售经理 → 组长 + 该小组；总经理/副总 → 总经理/副总经理；其他 → 普通成员），可再手动调整；
- 已经有账号的人在下拉里会标注「已有账号（职位）」并**不可重复选择**；改了职位就在列表里点「编辑」；
- 账号列表新增「组织架构」一列，显示该账号对应的 部门 / 小组 / 组织角色；非组织架构的账号（如系统管理员 `admin`）会标注「系统账号」。

> 组织架构数据来自工作台，可在「设置 → 组织架构」里同步最新；若某人不在列表里，先同步组织架构。

## 五、两种登录方式

1. **账号登录**（推荐给需要固定权限的人）：在「账号与权限」里从组织架构选人建号 + 选职位 + 设密码。
2. **组织架构登录**（无需建号）：用「英文名（如 vera）+ 统一初始密码」登录，系统按组织角色自动定范围：
   - 总经理办公室 / 总经理 / 副总 → 全部数据
   - 组织角色含「经理 / 主管 / 负责人」→ 本组数据
   - 其他人 → 只看自己

两者冲突时，**账号表优先**；想给某人固定权限，就建一个同名账号。

## 六、安全相关

- 密码以 PBKDF2-SHA256（21 万次迭代）加盐哈希存储，数据库中不存明文。
- 登录失败限流：同一 IP 10 分钟内失败 8 次、或同一 IP+账号失败 5 次 → 临时拒绝（429）。
- 每次登录（成功与失败）都写入「最近登录记录」，含时间、账号、来源 IP、说明，可随时排查异常登录。
- 账号可随时「停用」（保留记录，不能登录）或删除。
